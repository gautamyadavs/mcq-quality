## Why this matters pedagogically

The two transport paths produce identical validation reports because they
call the same `mcq_quality.core.validate_item` function. What differs is
the calling path:

- `validator_agent` imports from `mcq_quality.core` directly and calls it
  in-process. Fast, no subprocess, no MCP protocol overhead.
- `validator_agent_via_mcp` spawns the mcq-quality MCP server as a
  subprocess via stdio, sends a `call_tool('validate_mcq', ...)` request,
  parses the structured response, and returns the same dict.

The integration story: a workflow can act as an MCP client. Steps in a
workflow can call MCP tools the same way an AI client would. This is why
the three patterns (Skills, MCP, Workflows) layer rather than compete:
the workflow uses the MCP server's tools as steps in its pipeline; the
MCP server uses the same validator the skill bundles.
